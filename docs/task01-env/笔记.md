## 三、遇到的问题与解决

### 1. 系统里有两个 Python，默认指向 3.14

- **现象**：`py -0` 显示 `-V:3.14 *` 与 `-V:3.12`，直接敲 `python hello.py` 走的是 `AppData\Local\Programs\Python\Python314\python.exe`
- **原因**：电脑上原本装着 Python 3.14（随 VS 2026 安装），带 `*` 的是 py 启动器的默认版本
- **解决**：不卸载系统版本，改为**项目级隔离**——`py -3.12 -m venv .venv`，VS Code 选 `.venv`，此后项目内一律是 3.12.10
- **结论**：解释器版本问题应该在项目层解决，而不是改系统默认

### 2. uv 安装后命令不可用

- **现象**：`uv venv --python 3.12` 报「无法将 uv 项识别为 cmdlet」，`.venv` 因此没被创建，后续 `.venv\Scripts\python.exe` 也报「无法加载模块 .venv」
- **原因**：`uv` 未成功安装或未进 PATH；第二条报错是第一条的连锁反应
- **解决**：改用 Python 标准库自带的 `venv`（`py -3.12 -m venv .venv`），装包用 `py -3.12 -m pip`
- **结论**：先让链路跑通，工具可以后补；`venv` 是标准库，永远可用

### 3. 多行命令被写成一行 

- **现象 A**：`.venv\Scripts\python.exe --version.venv\Scripts\python.exe hello.py` → `unknown option: --version.venv...`
- **现象 B**：程序停在 `你叫什么名字？` 时写了三条 git 命令，结果名字变成了 `git add .git commit -m ...`
- **原因**：终端不按换行写内容；而程序等待输入时，**任何输入都会进入 stdin**
- **解决**：一次只打一行；看到程序在等输入时先跑通程序
- **结论**：不换行是零基础最高频的翻车点，凡是"等输入"的地方都要手打

### 4. 脚本中文输出乱码

- **现象**：脚本输出的中文变成 `浠?鎴叏灞?...`
- **原因**：脚本保存为「UTF-8 无 BOM」，Windows PowerShell 5.1 按 GBK 解析
- **解决**：另存为 **UTF-8 with BOM**（首字节 `EF BB BF`），乱码消失
- **结论**：给 Windows 写 PowerShell 脚本，一律存 UTF-8 with BOM

### 5. 截图脚本第二次运行报 `Add-Type 类型已存在`

- **现象**：同一终端里第二次运行 `拍.ps1` 报 `TYPE_ALREADY_EXISTS: CapHelper`
- **原因**：`Add-Type` 在同一 PowerShell 进程里重复注册同名 .NET 类型会失败
- **解决**：注册前判断 `if (-not ("CapHelper" -as [type]))`，让脚本**可重复执行**
- **结论**：脚本要幂等，能反复跑不报错

### 6. 截图分辨率只有 1707×1067，比屏幕低

- **现象**：屏幕是 2560×1600、缩放 150%，截图却只有 1707×1067，文字发虚
- **原因**：PowerShell 进程不是 DPI 感知的，系统按逻辑像素返回屏幕尺寸
- **解决**：截图前调用 `SetProcessDpiAwareness(2)`，之后按 2560×1600 原生分辨率采集
- **结论**：Windows 高 DPI 下做屏幕采集，必须先声明 DPI 感知

## 九、11/02 变量与流程控制（BMI v1）

**学了什么**
- `input()` 返回字符串，参与计算前必须 `float()` / `int()` 转换
- f-string 格式说明：`{bmi:.1f}` 中 `.1` 是精度、`f` 是小数形式；只写 `.1` 会变成科学计数法 `2e+01`
- `if / elif / else`：`elif` 只在前面条件都不成立时才检查，所以不用重复写 `bmi >= 18.5`
- `else` 是兜底，**不能带条件**

**遇到什么**
- 第一版四个分支全是 `elif`，没有 `else` 兜底 → 输入 1.70/95（BMI 32.9）时**一行判断都没有**，静默失败
- 边界值一开始写成 `< 23.9`，后来改成 `< 24`：否则 23.91~23.99 这些值会掉进"超重"档，和标准不符

**收获**
- 分支不完备是最隐蔽的 bug——不报错、只是"少说了话"。凡是分档判断，必须有 `else` 收口
- 四组数据 + 边界值全测一遍，才知道四个分支是否都真的能走到

## 十、11/03 函数（BMI v2）

**学了什么**
- `def 函数名(参数): ... return 结果`；参数是原材料，`return` 是成品
- **函数里要 `return` 不要 `print`**：print 只是显示，return 才把值交给调用者
- 拆分职责：`calc_bmi` 只算、`judge` 只判断、`advice` 只给建议、`main` 只管输入输出
- `if __name__ == "__main__":` 必须顶格，作用是"直接运行时才执行 main"

**遇到什么**
- `else:bmi>=28` 写法：Python 不报错（允许 `else:` 后跟简单语句），但那行比较被当普通表达式丢弃，能跑纯属运气
- `if __name__ == "__main__":` 缩进进了 `main()` 内部 → `main()` 永远不被调用，运行程序只有一行输出、没有输入提示
- 临时测试 `print(advice(18))` 忘了删，每次运行都多打一行

**收获**
- 从"照着步骤写"到"自己拆函数"是质变：**能单独测试一个函数**（`print(judge(18.5))`）不用重跑整个程序
- 拆函数带来一个新问题：`judge` 和 `advice` 各自写了一套判断，**逻辑重复**。正解是一个函数返回两个值（元组解包）：`return "偏瘦", "需要补充营养"` —— 11/04 优化
- 旧版本不用留副本，`git show 44796e4:bmi.py` 随时能看

## 三、遇到的问题与解决

### 1. 系统里有两个 Python，默认指向 3.14

- **现象**：`py -0` 显示 `-V:3.14 *` 与 `-V:3.12`，直接敲 `python hello.py` 走的是 `AppData\Local\Programs\Python\Python314\python.exe`
- **原因**：电脑上原本装着 Python 3.14（随 VS 2026 安装），带 `*` 的是 py 启动器的默认版本
- **解决**：不卸载系统版本，改为**项目级隔离**——`py -3.12 -m venv .venv`，VS Code 选 `.venv`，此后项目内一律是 3.12.10
- **结论**：解释器版本问题应该在项目层解决，而不是改系统默认

### 2. uv 安装后命令不可用

- **现象**：`uv venv --python 3.12` 报「无法将 uv 项识别为 cmdlet」，`.venv` 因此没被创建，后续 `.venv\Scripts\python.exe` 也报「无法加载模块 .venv」
- **原因**：`uv` 未成功安装或未进 PATH；第二条报错是第一条的连锁反应
- **解决**：改用 Python 标准库自带的 `venv`（`py -3.12 -m venv .venv`），装包用 `py -3.12 -m pip`
- **结论**：先让链路跑通，工具可以后补；`venv` 是标准库，永远可用

### 3. 多行命令被写成一行 

- **现象 A**：`.venv\Scripts\python.exe --version.venv\Scripts\python.exe hello.py` → `unknown option: --version.venv...`
- **现象 B**：程序停在 `你叫什么名字？` 时写了三条 git 命令，结果名字变成了 `git add .git commit -m ...`
- **原因**：终端不按换行写内容；而程序等待输入时，**任何输入都会进入 stdin**
- **解决**：一次只打一行；看到程序在等输入时先跑通程序
- **结论**：不换行是零基础最高频的翻车点，凡是"等输入"的地方都要手打

### 4. 脚本中文输出乱码

- **现象**：脚本输出的中文变成 `浠?鎴叏灞?...`
- **原因**：脚本保存为「UTF-8 无 BOM」，Windows PowerShell 5.1 按 GBK 解析
- **解决**：另存为 **UTF-8 with BOM**（首字节 `EF BB BF`），乱码消失
- **结论**：给 Windows 写 PowerShell 脚本，一律存 UTF-8 with BOM

### 5. 截图脚本第二次运行报 `Add-Type 类型已存在`

- **现象**：同一终端里第二次运行 `拍.ps1` 报 `TYPE_ALREADY_EXISTS: CapHelper`
- **原因**：`Add-Type` 在同一 PowerShell 进程里重复注册同名 .NET 类型会失败
- **解决**：注册前判断 `if (-not ("CapHelper" -as [type]))`，让脚本**可重复执行**
- **结论**：脚本要幂等，能反复跑不报错

### 6. 截图分辨率只有 1707×1067，比屏幕低

- **现象**：屏幕是 2560×1600、缩放 150%，截图却只有 1707×1067，文字发虚
- **原因**：PowerShell 进程不是 DPI 感知的，系统按逻辑像素返回屏幕尺寸
- **解决**：截图前调用 `SetProcessDpiAwareness(2)`，之后按 2560×1600 原生分辨率采集
- **结论**：Windows 高 DPI 下做屏幕采集，必须先声明 DPI 感知

### 7. `git push` 报 SSL 证书错误（Steam++ 加速所致）

- **现象**：`git push` 报 `SSL certificate OpenSSL verify result: unable to get local issuer certificate (20)`，但**浏览器能正常打开 GitHub**
- **原因**：Steam++（Watt Toolkit）开着 GitHub 加速——它把 `github.com` 等 40 多个域名写进 hosts 指向 `127.0.0.1`，并用自签 CA（`CN=SteamTools Certificate`）做中间人。系统与浏览器信任这个 CA，但 **Git 用 OpenSSL 自带的证书包，不认它**
- **排查**：`Get-Content C:\Windows\System32\drivers\etc\hosts` 看有没有 `127.0.0.1 github.com`；`Get-ChildItem Cert:\LocalMachine\Root` 找可疑自签 CA
- **解决**：`git config --global http.sslBackend schannel`（让 Git 改用 Windows 系统证书库），之后 push 立即成功
- **结论**：遇到"浏览器能上、git 不能上"的证书错误，先查 hosts 和系统证书库，八成是加速器/代理在做中间人

## 九、11/02 变量与流程控制（BMI v1）

**学了什么**
- `input()` 返回字符串，参与计算前必须 `float()` / `int()` 转换
- f-string 格式说明：`{bmi:.1f}` 中 `.1` 是精度、`f` 是小数形式；只写 `.1` 会变成科学计数法 `2e+01`
- `if / elif / else`：`elif` 只在前面条件都不成立时才检查，所以不用重复写 `bmi >= 18.5`
- `else` 是兜底，**不能带条件**

**遇到什么**
- 第一版四个分支全是 `elif`，没有 `else` 兜底 → 输入 1.70/95（BMI 32.9）时**一行判断都没有**，静默失败
- 边界值一开始写成 `< 23.9`，后来改成 `< 24`：否则 23.91~23.99 这些值会掉进"超重"档，和标准不符

**收获**
- 分支不完备是最隐蔽的 bug——不报错、只是"少说了话"。凡是分档判断，必须有 `else` 收口
- 四组数据 + 边界值全测一遍，才知道四个分支是否都真的能走到

## 十、11/03 函数（BMI v2）

**学了什么**
- `def 函数名(参数): ... return 结果`；参数是原材料，`return` 是成品
- **函数里要 `return` 不要 `print`**：print 只是显示，return 才把值交给调用者
- 拆分职责：`calc_bmi` 只算、`judge` 只判断、`advice` 只给建议、`main` 只管输入输出
- `if __name__ == "__main__":` 必须顶格，作用是"直接运行时才执行 main"

**遇到什么**
- `else:bmi>=28` 写法：Python 不报错（允许 `else:` 后跟简单语句），但那行比较被当普通表达式丢弃，能跑纯属运气
- `if __name__ == "__main__":` 缩进进了 `main()` 内部 → `main()` 永远不被调用，运行程序只有一行输出、没有输入提示
- 临时测试 `print(advice(18))` 忘了删，每次运行都多打一行

**收获**
- 从"照着步骤写"到"自己拆函数"是质变：**能单独测试一个函数**（`print(judge(18.5))`）不用重跑整个程序
- 拆函数带来一个新问题：`judge` 和 `advice` 各自写了一套判断，**逻辑重复**。正解是一个函数返回两个值（元组解包）：`return "偏瘦", "需要补充营养"` —— 11/04 优化
- 旧版本不用留副本，`git show 44796e4:bmi.py` 随时能看

## 十一、11/04 异常处理与类型提示

**学了什么**
- `try / except <具体类型>`：程序出错时不崩，跳到 except 里执行
- 常见异常：`ValueError`（格式不对）、`ZeroDivisionError`（除零）、`FileNotFoundError`、`KeyError`
- **异常管不了逻辑错**，所以还要做范围校验：`if height <= 0 or weight <= 0: return`
- 类型提示：`def calc_bmi(height: float, weight: float) -> float`，**运行时不检查**，只给编辑器和人看；任务一验收明确要求"带类型提示"
- 元组解包：`return "偏瘦", "需要补充营养"` → `label, tip = judge(bmi)`，用来消除 judge/advice 的重复判断

**遇到什么**
- 把整段 `main()` 代码粘贴时**覆盖了整个文件**，三个函数全没了、入口也没了 → 运行**不报错、什么都不输出**
- `else:bmi>=28` 这种写法不报错但无意义（那行比较被当普通表达式丢弃）
- `if __name__` 缩进进 `main()` 里，导致 `main()` 永远不被调用

**收获**
- "不报错但没反应"的三步排查：①文件末尾有没有调用入口 ②用到的函数都定义了吗 ③文件保存了吗
- **改代码只改一个函数**，不要把片段当整文件粘贴

## 十二、11/05 类（class）

**学了什么**
- `class BMI:` + `def __init__(self, height, weight)`：创建对象时自动执行的构造函数
- `self` = "这个对象自己"；方法的第一个参数必须是 `self`，调用时不用传
- 方法里访问属性用 `self.height`、`self.weight`；调用别的方法用 `self.value()`
- 类的价值：把"数据"和"操作数据的方法"打包；同时算多个人时数据互不干扰

**遇到什么**
- `def judge` / `def report` **顶格**了（没缩进进类）→ `AttributeError: 'bmi' object has no attribute 'report'`
- 修好后 `return (...)` 那一行的缩进从 8 格掉到 4 格 → **`SyntaxError: 'return' outside function`**

**收获**
- **缩进阶梯**：`class` 0 → 方法 4 → 方法体 8 → 方法里的 if 块 8 → if 里的 return 12
- 一条通用规则：**凡行尾是冒号，下一行必须多缩进 4 空格**
- 选择 `编辑区选中多行` → `Tab` 整体缩进，比手敲空格可靠

## 十三、11/06 异步入门（async / await）

**学了什么**
- 为什么需要异步：三个各 1 秒的任务，串行 3 秒、并发 1 秒
- `async def` 定义协程；`await` 在这里等，同时把 CPU 让给别人；`asyncio.run(main())` 启动事件循环
- `asyncio.gather(*tasks)` 并发执行多个协程，返回顺序与传入一致
- **`time.sleep` 会卡住整个程序，`asyncio.sleep` 才会让出**——在 async 函数里永远用后者
- 异步函数也能写类型提示：`async def task(name: str, sec: float) -> str`

**遇到什么**
- 定义了**两个 `main`**，后一个覆盖前一个 → 只有一个测试跑到，且**不报错**
- 文件建到了 `.venv\` 里面（还多了个下划线），不在项目根目录

**收获**
- **同名函数会互相覆盖且不报错**，是"少做事"类 bug 的典型；用 `Ctrl+Shift+O`（大纲）能看出重名
- 实测数据：串行 3.03 秒 vs 并发 1.01 秒（快 3 倍）

## 十四、11/07 httpx 真实并发请求

**学了什么**
- `httpx` 是支持异步的 HTTP 客户端（`requests` 只能同步）
- 写法：`async with httpx.AsyncClient() as client:` → `await client.get(url, timeout=10.0)`
- **`AsyncClient` 要复用**（内含连接池），不要每个请求新建
- `asyncio.gather(*tasks)` 里 `*` 是解包：把列表拆成多个参数
- 异常处理要**从具体到宽泛**：先 `except httpx.TimeoutException`，再 `except httpx.HTTPError`（后者是前者的父类）
- `requirements.txt`：`pip freeze` 导出，别人一条 `pip install -r` 就能复现环境

**遇到什么**
- 一屏截不下 55 行代码 → 缩小字号（`Ctrl + -`）后一次拍全
- 并发只有 2 倍而不是 3 倍：每次请求除了 `delay` 还有 TLS 握手、网络往返约 0.8 秒开销

**收获**
- **串行 = 相加（Σ），并发 = 取最慢（max）**——用 1/2/3 秒三个地址实测：串行 8.33 秒，并发 4.85 秒
- 联网失败不会崩：两个 except 分别兜住超时和其他网络错误
